## 1. Problem statement

Signature-based controls detect known attacks. They fail against novel
intrusions and against patient attackers who never trip a fixed rule. AEGIS
learns per-entity behavioural baselines from access logs and scores deviations,
producing an explainable risk score and an attack-type hypothesis.

The system must handle sequential behaviour, extreme class imbalance
(~1% of events), concept drift in legitimate behaviour, explainability for a
SOC analyst, and cold-start entities with little or no history.

## 3. Architecture

See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the full component map and the
production mapping. Decision rationale is in [`DECISIONS.md`](DECISIONS.md).

Summary: a hybrid detector — per-entity statistical baselines and a Markov
resource-transition model feed engineered behavioural features into an
IsolationForest anomaly detector; a supervised RandomForest assigns an attack
category; a weighted risk engine produces a 0–100 score; a deterministic
explainer attributes the decision to named factors.

## 5. Evaluation protocol

Fixed before any model was trained (see `src/evaluation/metrics.py`):

- **Split.** Temporal only — earlier window trains, strictly later window tests.
- **Operating point.** Top `alerting.budget_fraction` (1%) of events by risk,
  selected as an exact top-k with deterministic tie-breaking.
- **Primary metric.** PR-AUC, because at ~1% prevalence ROC-AUC is optimistic
  and accuracy is meaningless (predicting "normal" always scores ~99%).
- **Also reported.** Precision, recall, F1 and false-positive rate at the
  budget; per-attack precision/recall/F1; confusion matrix; campaign-level
  detection coverage and time-to-first-alert; a capacity sweep showing what
  recall costs in analyst workload.
- **Reproducibility.** Master seed `20260725`; every metrics document carries a
  manifest.
